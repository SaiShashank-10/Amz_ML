# Chakravyuh — Business Entity Resolution (v7)

Members: Kommu Hemasree (Leader), Kancharla Sunaina, Vakada Kushal, and
Vakkalanka Sai Shashank.

The submitted pipeline is the v7 positive-link rescoring cascade. It trains
baseline, v3 and v4 LightGBM classifiers on supplied labels, generates v4
preliminary predictions, and then scores every preliminary positive pair with
the frozen v4 classifier. Final thresholds are 0.65 for Source 2 and 0.75 for
Source 3. The final candidate file records precisely the pairs scored by this
last classifier. Historical scripts are included for audit; the entry point
below does not apply the rejected v5 recovery or v6 ambiguity policies.

## Environment

Tested on Windows, Python 3.13.3, with the pinned requirements. From the
extracted ZIP's `code/business_entity_resolution/` directory:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r .\requirements.txt
```

After installation the pipeline operates offline, using only the supplied
challenge data. No external business lookup, geocoder, dataset or pretrained
model is used. LightGBM and the trained tree models are MIT licensed and far
below eight billion parameters; see LICENSE and licenses/.

## Complete reproduction: training, offline assessment, test predictions

DATASET must contain the original train/ and test/ directories and all seven
provided TSV files. Run from `code/business_entity_resolution/`:

```powershell
.\.venv\Scripts\python.exe -u .\src\reproduce_submission.py --data-dir "C:\path\to\student_resource\dataset" --work-root "C:\path\to\fresh_v7_reproduction" --workers 4
```

Use a new or empty work directory. The runner performs actual supervised
training, development threshold selection, independent assessment, full test
inference and validation. Both regenerated TSVs are placed in the work root's
`output/` directory. The ZIP's root output/ retains the original submission.
The runner sets the working directory for all modules and prints log paths.

To print the exact ordered commands without running them:

```powershell
.\.venv\Scripts\python.exe .\src\reproduce_submission.py --data-dir "C:\path\to\student_resource\dataset" --work-root "C:\path\to\fresh_v7_reproduction" --workers 4 --dry-run
```

Training uses 30,000 baseline references and separate 60,000-reference samples
for v3/v4. Retrieval searches all supplied Source 2/3 records. This is sampled
supervised fitting, not fitting on every labeled reference. Development uses
30,000 further references, generated by ordered 10,000 then 30,000 sampling
calls with distinct seeds. Final assessment uses 10,000 references excluding
all earlier fitting and development samples. Final inference requires the
same positive paired-improvement confidence interval guard as production.

Allow many hours and at least 45 GB free disk beyond the input data; more is
advisable. Four workers are the conservative setting used with 16 GB RAM;
large training matrices may need a pagefile. Do not run concurrent jobs in the
same work root. Inspect the stage log printed by the runner, for example:

```powershell
Get-Content "C:\path\to\fresh_v7_reproduction\artifacts_v7\finish.log" -Tail 20 -Wait
```

The runner rejects nonempty work roots to prevent mixing runs. On interruption,
inspect the failed stage log and use the individual commands printed by
--dry-run to resume. Individual inference stages checkpoint completed chunks.
Models, samples, feature matrices, indexes and logs are retained in the work
root; none must be downloaded or copied from the original developer workspace.

## Validation and offline score

From `code/business_entity_resolution/`, validate the ZIP's original outputs:

```powershell
.\.venv\Scripts\python.exe .\src\validate_streaming.py --output-dir ..\..\output --test-dir "C:\path\to\student_resource\dataset\test"
.\.venv\Scripts\python.exe .\src\validate_submission.py --matching ..\..\output\matching_results.tsv --test-dir "C:\path\to\student_resource\dataset\test" --check-ids
Get-Content .\reports_v7\metrics.json
```

Streaming validation checks both files, exact headers, every reference,
target-ID existence, duplicate-free rows/lists and match inclusion in
candidates. The unmodified official matching-file check also verifies ID
existence. Run it from this code directory to avoid automatically loading the
large candidate file; streaming validation checks that file independently.

The independent v7 macro-F0.5 is 0.9740168111 on 10,000 held-out training
references. Per-reference scoring is 1.25*TP/(0.25*true_count+predicted_count),
with 1 for a correctly empty singleton and 0 for a false merge on a singleton.
This is not the test leaderboard score. v4 achieved participant-reported
0.962; the participant selected v7, whose leaderboard score is unreported.
No 0.992 score or rank is guaranteed. France has no provided validation labels.

## Source and evidence

All source is under src/. `reproduce_submission.py` is the entry point.
`pipeline.py` and `enhanced_pipeline.py` implement the baseline and v3;
`phonetic_features.py`, `phonetic_index.py`, `phonetic_pipeline.py`, and
`hybrid_pipeline.py` implement v4. `empty_recovery.py` recreates baseline
assessment caches (its rejected recovery predictions are not submitted).
`match_rescore.py`, `calibrate_rescore.py` and `finish_rescore.py` implement
the final classifier and threshold stages. `test_pipeline.py` contains
normalization, scoring and candidate consistency checks.

models/, models_v3/ and models_v4/ contain completed trained artifacts;
reports*/ contain assessment and validation evidence. The root methodology
document is Documentation_template.md; SHA256SUMS.json covers all archived
files except itself. Supplied data and large intermediate caches are excluded.
The completed outputs cover 1,732,544 references, 5,702,473 final candidates
and 5,641,306 matches, including 259,452 France references.

Final packaging did not rerun the full training job. Original completed
training/inference evidence is included. Added orchestration preserves the
training, feature, threshold and inference definitions. Hardware/library
differences can affect retraining numerics; the archived outputs and models
are the original completed submission artifacts.
